DIP-FP-132-FP-133-FP-134-mobile
Story Summary
Combines three RSVP-surface stories that touch the same components and share a hard dependency chain: FP-132 adds in-app "you haven't responded yet" prompts (My Events list + Event Detail); FP-133 (mobile half) makes RSVP editability and closure-aware, replacing the current effective_status === "SCHEDULED"-only check with the new server-computed rsvp_closure_at cutoff (web half merged in PR #77, not yet in dev); FP-134 schedules up to 3 local push nudges per event for members who still haven't responded, anchored to that same cutoff, using the tenant's configurable day-offsets (also from PR #77). All three read/write the same two components (RsvpControls, EventListItem) and the same reconciliation call sites — splitting them would mean three DIPs editing the same lines.
Not covered — deliberately excluded: FP-127 (RSVP "Tentative" option) touches the same label surfaces per its Jira note, but is unscoped (needs live verification of the rsvps status constraint first) and not combined here — when FP-127 lands, its DIP must revisit the null-case label logic this DIP adds to account for a third response value.
Repo Target
Mobile (Expo/React Native) — owgc-tech/flockpulse-mobile.
